# 光之回响设计：动态 CG 特写（AI 旁白式情景生成）

**日期**：2026-08-17
**状态**：设计三节已获用户逐节确认（决策表 + 技术选择 A+A）；待写实施计划
**范围**：特写 CG 动态化 —— LLM 编生活情景 → ComfyUI 后台生成半身情景 CG → 头像门控 → 图文同源旁白；单角色（白月）试点，跑通后复制到 6 人
**依赖**：在途 avatar-closeup 计划（docs/superpowers/plans/2026-08-16-avatar-closeup.md）的特写视图为其显示面，执行顺序在途计划先行

## 1. 背景与目标

用户在 avatar-closeup 重构（头像浮层 + 全屏特写）基础上提出：特写 CG 不应是静态一张，而是像酒馆（SillyTavern）旁白一样由 AI 延续 —— 用户提供起始 CG，AI 编随机生活情景并在后台生成新 CG，玩家每次点击头像都看到角色生活的新一页。参考成熟案例「智绘姬」（酒馆通用生图插件：LLM 编 prompt + 后台预生成 + 无感换图）。

## 2. 已确认的需求决策

| 决策项 | 结论 |
|---|---|
| 情景来源 | LLM 现编（旁白式）：情景文案 + 生成 prompt + 旁白三者同源（bridge 里的对话 AI 产出） |
| CG 构图 | 半身情景图 1216×832（角色 + 环境） |
| 图文关系 | 图文同源：进入特写先放旁白交代画面，对话从该情景自然展开 |
| 缓存策略 | 存盘续用，每角色上限 8 张，自动删最旧（磁盘 ≤ ~53MB，实测 1216×832 PNG ≈ 1.11MB/张）；收藏免删机制可后续再加 |
| 试点范围 | 单角色（白月）跑通完整链路，验证质量/时长后复制到其余 5 人 |
| 头像门控 | 生成期间场景内该角色头像隐藏（不可点）；生成失败/ComfyUI 未开 → 头像保留、静态立绘兜底 |
| 起始 CG | 用户提供（白月躺沙发玩手机，1216×832 含环境）；后续 5 人各 1 张同规格 |
| 身份锚定 | 起始 CG 做 img2img 参考 + 情景文案（复用已验证参考图配方：denoise 0.7 / 45 步 euler_ancestral），不累积漂移 |
| 触发时机 | 消耗即触发（MVP）：进入特写即触发下一张生成；智绘姬式进场景预取作为跑顺后的未来优化 |

## 3. 交互流程总览

```
开局（起始 CG：白月躺沙发玩手机）
        │ 玩家点击头像
        ▼
┌─── 全屏特写：CG #1 + 旁白「白月正窝在沙发里刷手机…」+ 对话输入框 ───┐
│   （同时后台：LLM 编下一情景「白月在厨房做饭」→ ComfyUI 生成）      │
└──────────────────────────────────────────────────────────────┘
        │ 关闭特写 → 场景里白月头像【隐藏】（生成中，不可点）
        │ 生成完毕（约 1-3 分钟）→ 头像重现
        │ 再点 → CG #2（厨房做饭）+ 对应旁白，同时生成 CG #3 …循环
```

## 4. 架构与模块划分

**服务端（Python，跑在 bridge 进程里）**

| 模块 | 职责 |
|---|---|
| `server/cg_generator.py`（新） | CG 生成器：串行队列（同一时间只跑一张）、LLM 编情景、ComfyUI 提交（img2img 工作流）、落盘 + 8 张上限清理 |
| `server/bridge.py`（改） | 挂载 `POST /cg/generate`（触发生成）、`GET /cg/status?char=xx`（状态查询）；启动时初始化生成器 |

**前端（JS）**

| 模块 | 变更 |
|---|---|
| `js/state.js`（改） | `sceneCharacters[charId]` 加 `cgGenerating`（bool）、`cgCurrent`（当前 CG 文件名）；`cgHistory`（列表）进存档 |
| `js/scene.js`（改） | 头像渲染加门控：`cgGenerating === true` → 该角色头像不渲染 |
| `js/closeup.js`（在 avatar-closeup 计划 Task 3 基础上改） | 特写图源：CG（优先）→ `neutral.png` 静态兜底；进入特写时注入旁白 + `POST /cg/generate` |
| 轮询（scene.js 或 app.js） | 特写关闭后每 5s 查 `/cg/status`，就绪 → 更新状态、头像重现 |

**数据流**

```
点击头像 → 特写显示当前 CG + 旁白（图文同源）→ POST /cg/generate
后台：LLM 编情景（角色人设 + 游戏时间/场景 + 历史 CG 情景列表防重复）→ JSON{narration, prompt}
     → ComfyUI img2img（起始 CG 参考 + 情景 prompt，1216×832，denoise 0.7）
     → 落盘 assets/characters/<id>/cg/<seq>.png + 超 8 张删最旧 → 状态置 ready
前端：轮询发现 ready → cgCurrent 更新、cgGenerating=false → 头像重现
```

## 5. 错误处理与降级

| 场景 | 处理 |
|---|---|
| ComfyUI 未运行（8188 不通） | 触发时探测失败 → 头像不隐藏、特写用静态立绘、控制台提示「CG 生成不可用」 |
| LLM 编情景失败 | 重试 1 次；仍失败 → 本轮放弃，头像恢复、静态兜底 |
| 同角色已有 pending 生成 | 幂等：不再重复提交 |
| 生成中玩家离开场景 | 生成照常完成落盘，回来自动可用 |
| 生成中关闭游戏 | bridge 进程退出，本轮结果不进 assets（ComfyUI 输出目录留底），重开游戏触发新生成即可 |
| 存档时正在生成 | `cgGenerating` 为会话态不持久化；读档后头像直接可点，特写显示 `cgCurrent` 或静态兜底 |

## 6. 测试与验收

- **bridge 冒烟**：扩展 smoke 脚本验证 `/cg/generate`、`/cg/status` 接口形状与错误路径（无 API key 时）
- **生成链路试点**：跑一张白月情景 CG，人工审查画风/一致性/耗时
- **浏览器回归**：头像门控（隐藏→重现）、CG 显示、旁白注入、静态兜底（关掉 ComfyUI 的场景）
- **存档恢复**：`cgHistory` / `cgCurrent` 持久化一致
- **真机 LLM 端到端**：需 API key（属 Task 12 遗留，非本轮阻塞）
