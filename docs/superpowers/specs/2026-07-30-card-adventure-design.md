**日期：** 2026-07-30
**状态：** 待审批
**类型：** 全栈前端应用（无后端）

## 1. 项目概述

### 1.1 核心概念

一款融合 AI 驱动文字冒险与游戏王风格卡牌对战的 Web 应用。玩家进入 Ori 空灵森林美学风格的互动故事书，AI 驱动的叙事文本流式呈现。当剧情触发战斗时，画面过渡到全屏对战舞台（仿游戏王大师决斗布局），玩家操控预设卡组与 AI 对手对战。

### 1.2 美学方向

- **参考来源：** Ori and the Blind Forest / Ori and the Will of the Wisps
- **视觉基调：** 空灵、发光、手绘感、深色背景 + 辉光粒子
- **色彩体系：**
  - 主色调：灵火蓝（#4FC3F7）、Spirit Green（#81C784）
  - 点缀：暖金辉（#FFD54F）
  - 对战场景：蓝紫 vs 暗红对立色
- **字体：** 霞鹜文楷（正文，手写感）、思源黑体（UI 标签）、Cinzel（英文标题）、Inter（英文正文）
- **图标库：** Lucide Icons（SVG，轻量专业）

### 1.3 游戏流程

```
标题界面 → 配置API Key → 选择/新建存档 → 进入故事
  故事主线（AI 叙事 + 世界书 + MVU + 正则）
    ↓ 剧情触发战斗标记 [BATTLE:卡组名]
  全屏对战舞台（游戏王简化规则）
    ↓ 战斗结束
  回到叙事（战斗结果影响后续剧情）
```

## 4. 文字冒险模块设计

### 4.1 核心引擎（SillyTavern 兼容）

| 引擎 | 文件 | 功能 |
|------|------|------|
| LLM API | `llm.ts` | OpenAI 兼容接口、流式输出、多供应商支持（DeepSeek 等） |
| 提示词组装 | `prompt.ts` | 系统提示 + 历史 + 世界书注入 + MVU 快照 + 用户输入 |
| 世界书 | `worldbook.ts` | JSON 格式世界书加载、关键词匹配（大小写敏感/全词/递归）、token 预算控制 |
| MVU | `mvu.ts` | JSON Patch 状态追踪、物品/线索/NPC 自动提取 |
| 正则引擎 | `regex-script.ts` | AI 输出后处理、格式规范、骰子解析、战斗标记提取 |
| 斜杠命令 | `slash-command.ts` | `/roll`、`/var`、`/save`、`/load`、`/help` |
| 骰子 | `dice.ts` | d100、3d6 等通用骰子 |

### 4.2 LLM 对话流程

```
用户输入
  → 世界书匹配 → 注入关键词上下文
  → MVU 状态快照 → 注入当前世界状态
  → 提示词组装（系统提示 + 历史 + 状态 + 用户输入）
  → API 请求（流式 SSE）→ 逐 token 渲染到 NarrativeText
  → 正则后处理（骰子解析、战斗标记检测、格式修正）
  → MVU 自动更新
  → 生成行动选项，隐藏到展开按钮后
```

### 4.3 行动选项 UI

- 默认隐藏在可折叠面板中
- 点击底部「展开行动选项」按钮展开 2-4 个选项卡片
- 单击选项填入输入框，双击直接提交
- 选项卡片有交错入场动画（stagger delay）

### 4.4 斜杠命令

| 命令 | 说明 |
|------|------|
| `/roll NdM` | 掷 N 个 M 面骰子 |
| `/var set key value` | 设置 MVU 变量 |
| `/var get key` | 查看变量 |
| `/save` | 手动存档 |
| `/load` | 加载存档 |
| `/help` | 帮助列表 |

## 5. 卡牌对战模块设计

### 5.1 规则引擎（简化版游戏王）

**场地布局：**
- 怪兽区：5 格 × 双方
- 魔法陷阱区：5 格 × 双方
- 额外怪兽区：1 格（共享，融合/Xyz/Link 共用）
- 卡组 / 墓地 / 额外卡组：侧边区域

**五阶段流程：**
- 抽牌阶段 → 主要阶段1 → 战斗阶段 → 主要阶段2 → 结束阶段

**召唤规则：**
- 通常召唤：1 回合 1 次，4★以下直接出，5-6★需 1 只祭品，7+★需 2 只祭品
- 融合召唤：通过卡牌效果将手牌/场上素材送入墓地，从额外卡组特殊召唤
- Xyz 召唤：同等级怪兽 N 只叠放
- Link 召唤：素材数量满足 Link 值

**战斗规则：**
- 攻击表示 vs 攻击表示：ATK 较高方破坏较低方，差值扣 LP
- 攻击表示 vs 守备表示：ATK > DEF → 破坏守备怪兽（不扣 LP）；ATK < DEF → 差值反伤攻击方 LP
- 直接攻击：对方场上无怪兽时可直接攻击玩家 LP

**简化连锁（2 层上限）：**
- 响应时机：召唤时 / 攻击宣言时 / 效果发动时
- 行动方行动 → 对方可响应（最多1次） → 结算（响应卡先结算）
- 不支持自排连锁

**LP：4000 起**

**去掉的机制：**
- 速攻魔法/反击陷阱的精细时点划分
- 伤害步骤细分
- 除外区
- 同调/灵摆/仪式召唤
- 主卡组数量限制

### 5.2 卡牌数据

从 `cards.cdb`（YGOPro 数据库）提取 3 个卡组涉及的全部卡牌，约 35 种：
- 虫惑魔：特莱恩、兰卡、基诺、蒂奥、破洞露蒂亚、芙莉西亚(Xyz R4)、塞拉(Link-1)、阿蒂普丝(Link-2+)、墓穴洞、狂惑的落穴、连锁空穴、虫惑之园
- 珠泪：塞壬人鱼、雷诺哈特、小美人鱼、梅洛人鱼、卡雷多哈特(融合)、鲁莎卡人鱼(融合)、壹世坏系列魔陷
- 主角：奇袭的又佐、重装武者-弁庆、恐龙摔跤手、增援、万宝槌、强欲而谦虚之壶、恶魔之斧、凶暴化之假面、魔导师之力、圣剑加拉廷、盾牌猛击

### 5.3 AI 对手

自写 TypeScript AI，三种策略：

| 卡组 | 策略 | 行为优先级 |
|------|------|-----------|
| 虫惑魔 | 防守反击 | 盖陷阱 > 召唤检索怪兽 > Xyz/Link 召唤 > 攻击 |
| 珠泪 | 堆墓融合 | 送墓效果触发 > 融合召唤 > 盖魔陷 > 攻击 |
| 主角 | 装备 Beat | 通常召唤战士 → 装装备卡 → 高 ATK 攻击 |

AI 每回合核心循环：
```
1. 抽牌阶段自动抽牌
2. 主1: 检查手牌，选择最优召唤策略
3. 主1: 有可盖放魔陷就盖放
4. 战斗: 能攻击就攻击（优先攻击 ATK 最低的怪兽）
5. 主2: 如有剩余可操作则继续
6. 结束
```

```
                   ┌──────────────┐
                   │  IndexedDB   │
                   │  (Dexie)     │
                   └──────┬───────┘
                          │ 持久化
    ┌──────────┐    ┌─────┴──────┐    ┌──────────┐
    │ Story    │◄──►│  Zustand   │◄──►│ Battle   │
    │ Store    │    │  (全局)    │    │ Store    │
    └────┬─────┘    └─────┬──────┘    └────┬─────┘
         │                │                │
    ┌────┴────┐     ┌────┴────┐      ┌────┴────┐
    │ 故事书   │     │ 导航/设置 │      │ 对战舞台 │
    │ 组件     │     │ 组件     │      │ 组件     │
    └─────────┘     └─────────┘      └─────────┘
```

**触发对战流程：**
1. AI 叙事输出中包含 `[BATTLE:虫惑魔]` 标记
2. 正则引擎解析到战斗标记
3. BattleStore 设置 `{active: true, opponentDeck: '虫惑魔'}`
4. BattleOverlay 全屏渲染，引擎初始化卡组
5. 战斗结束 → BattleStore 重置 → 叙事继续

## 8. 持久化设计

**IndexedDB (Dexie) 表结构：**

| 表 | 内容 |
|------|------|
| `saves` | 存档元数据（名称、时间戳、预览文本） |

| `battleState` | 当前卡组、LP、场上状态 |
| `deckData` | 玩家卡组配置 |

## 9. 约束与范围

### 9.1 范围内

- 文字冒险完整引擎（世界书/MVU/正则/斜杠命令）
- 流式 AI 叙事输出
- 全屏对战舞台（游戏王简化规则）

- 卡组查看界面
- 设置面板（API Key 配置等）
- Ori 美学 UI
- IndexedDB 自动存档
- 纯静态部署

### 9.2 范围外

- 后端 API 服务器
- 真实网络对战
- YGOPro 引擎直接集成
- 超过 3 套的 AI 卡组
- 音频系统（仅预留界面）
- 移动端完整适配（保留响应式基础，优先桌面）
- 用户自定义卡组上传
