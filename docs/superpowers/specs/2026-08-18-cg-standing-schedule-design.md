**日期**：2026-08-18

**范围**：点击场景内角色头像 → 播放 CG（3 秒，如有）→ 立绘居中 → 场景背景淡入 → 对话常驻；9 角色按手写行程表在场景间走动（按游戏时间派生在场）；场景调整（删 3 公司场景、新增 3 场景）

## 1. 背景与目标

阵容替换完成后（世界书 9 人），用户提供了两批素材：桌面「初始CG」（8 张 1216×832 情景横图）与「抠图立绘」（9 张 832×1216 透明底立绘）。本设计实现：

1. **特写序列**：点击场景内角色头像后，全屏特写先播该角色 CG 3 秒，交叉渐变切换为立绘居中，随后当前场景背景淡入立绘身后，对话区常驻（VN 形态）。
2. **角色行程表**：9 角色不再固定位置，改为按游戏时间（4 时段）在场景间走动的手写行程表；落位带小幅随机；行动文案注入对话上下文供 AI 自然解释。
3. **场景调整**：删除 3 个公司场景（阵容已无职场角色），新增 3 个场景（双子的房间/教堂/森林，用户已出背景图）。

## 5. 角色行程表（手写，4 时段）

时段划分：**上午 6-12 / 下午 12-18 / 晚上 18-24 / 深夜 0-6**。双子 CG 白天/夜晚切换点 = 18:00，与该划分一致。

| 角色 | 上午 | 下午 | 晚上 | 深夜 |
|---|---|---|---|---|
| 塞壬 | 客厅·鱼缸里打盹 | 客厅·泡水吐泡泡 | 客厅·盯着主角看 | 卧室·睡 |
| 零依 | 客厅·活跃气氛 | 商业街·元气逛街 | 客厅·缠着主角 | 卧室·睡 |
| 露世 | 卧室·安静看书 | 客厅·沙发角落看书 | 客厅·冷眼观察 | 卧室·睡 |
| 姬丝吉尔 | 双子的房间·直播 | 双子的房间·直播 | 客厅·串门调戏 | —·怪盗行动 |
| 璃拉 | 双子的房间·半梦半醒陪播 | 双子的房间·抱鲨鱼玩偶打瞌睡 | 客厅·半梦半醒 | —·怪盗行动 |
| 艾克利西亚 | 包子铺·帮工 | 小吃街·帮工 | 客厅·讨要投喂 | 卧室·睡 |
| 天童 | 客厅·怯怯跟着主角 | 卧室·用袖子挡脸躲着 | 客厅·和事佬劝架 | 卧室·睡 |
| 理 | 教堂·静思祈祷 | 商业街·探索都市 | 客厅·分享见闻 | 卧室·睡 |
| 彩虹 | 客厅·包揽家务 | 森林·野外写生 | 客厅·专心画画 | 卧室·睡 |

机制要点：

1. **在场派生**：某场景当前时段的在场角色 = 行程表中该时段位于该场景的角色；`—` 表示不在任何场景（头像不渲染，如深夜双子）。
2. **重算时机**：进入场景时、游戏时间跨过时段边界时（在场景内停留期间）。
3. **落位随机**：每角色每场景一个基准点（实现阶段按场景构图设定合理默认），每次进入场景在基准点 ±3% 范围内随机偏移；同场景多角色基准点错开。
4. **数据存放**：`data/schedules.json`（行程表 + 行动文案 + CG 路径表 + 基准点）；纯静态数据，不依赖网络/LLM。
5. **存档**：行程表为静态数据、在场为派生态 → 无需存档迁移；读档后按当前游戏时间重算在场。
6. **色色分类**：`event.js` 的 `LOCATION_HEROINES` 静态表改为按行程表动态判断「当前地点当前时段有无女主在场」。

## 6. 点击头像显示序列

```
点击场景内角色头像
    │
    ├─ 有 CG（getCgPath(charId, gameTime) 命中，且 Image 加载成功）
    │        → 全屏 CG 显示 3 秒（object-fit: contain，铺满特写层）
    │        → 0.4s 交叉渐变
    │
    └─ 无 CG（艾克利西亚未补图 / 路径未配置 / 图片加载失败）
    │        → 直接进入立绘
    ▼
抠图立绘（standing.png）居中，最大高度 ≈ 78vh
    │ 0.6s 淡入
    ▼
当前场景背景淡入立绘身后（特写层底图 = 场景 bg，立绘前景，对话区底部）
    → 常驻对话形态（VN 式），Esc / 关闭按钮回场景
```

- 对话区在序列结束后可用；序列播放中玩家可跳过（点击任意处提前结束 CG 段，进入立绘形态）。
- 双子 CG 按 `gameTime.hour < 18 ? start-day : start-night` 解析（深夜双子不在场，实际 18-24 时段为夜晚版）。
- 立绘加载失败 → 沿用现有降级链（neutral.png → fullbody.png → 「立绘缺失」占位），不进入 CG 段。

## 7. 对话上下文注入

点击角色打开特写/对话时，`js/ai.js` 在发给 bridge 的上下文中追加一行：

```
【当前场景】<场景名>（<当前时段>）
【角色状态】<角色名>：<行动文案>（如「塞壬懒洋洋泡在鱼缸里，正盯着你看」）
```

对话 LLM 据此自然解释角色为何在此、在做什么。LLM 未配置时，对话区直接展示行动文案文本（不阻塞）。

## 9. 错误处理与降级

| 场景 | 处理 |
|---|---|
| CG 文件缺失/加载失败 | 跳过 CG 段直接立绘（Image onerror），无报错弹窗 |
| 立绘文件缺失 | 沿用现有降级链（neutral.png → fullbody.png → 占位） |
| 场景背景缺失 | 特写层用深色底（现有特写底色），对话不受影响 |
| LLM 未配置/调用失败 | 对话区显示行动文案纯文本；现有对话错误处理不变 |
| 存档时在场状态 | 派生态不持久化，读档后按时间重算（无需迁移） |
| 行程表数据损坏 | `validate-schedules.mjs` 在开发期拦截；运行时查询有默认兜底（返回空在场） |
